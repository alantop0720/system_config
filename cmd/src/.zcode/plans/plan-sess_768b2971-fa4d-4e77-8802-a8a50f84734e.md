## 目标

给 `cmd` 工具增加「命令行传序号直接执行」能力：`cmd dhcp 1` 直接执行 `/opt/cmd/dhcp` 菜单中的第 1 项，不再弹出"请输入要执行的序列号"交互；不带参数时（`cmd dhcp`）保持原有交互菜单行为不变。

## 改动内容

### 1. `cmd/src/c/cmd.c`（核心，约 10 行改动）

`main()` 中在 `processCommandFile()` 返回、`commandCount` 校验之后（现第 148 行处）：

- 若 `argc >= 3`（即带了序号参数）：`choice = atoi(argv[2])`，跳过 printf 提示、`scanf` 和清缓冲区这三段交互代码。
- 否则：保持原样（提示输入、scanf、清缓冲区）。
- 原有的序号范围校验（`choice < 1 || choice > commandCount` → "无效的序列号"）位置不动，两种方式共用——非数字参数 atoi 得 0，会被安全拦截。
- 之后的执行分发逻辑完全不动：flag=1 直接 `system()` 执行；flag=0 仍走 `[key]` 运行时交互输入（dhcp 6 项全是 flag=1，不受影响）。
- 菜单列表仍会在解析时打印出来（现有行为），随后直接执行选中的命令，输出透明可查。

### 2. `cmd/readme`（帮助文档，`cmd` 无参数时显示）

- 新增一行用法说明：`cmd 菜单名 序号 可直接执行对应菜单项，例如 cmd dhcp 1`
- 更新日期改为 2026.09.06

### 3. `cmd/src/c/AGENTS.md`

补一句说明 CLI 用法（`cmd <菜单>` 交互选择 / `cmd <菜单> <序号>` 直接执行），保持文档与代码同步。

## 验证方式

- 本机（Windows）如有 gcc 则跑 `gcc -fsyntax-only cmd.c` 做语法检查；程序硬编码 `/opt/cmd` 路径，运行验证需在 Linux 服务器上。
- 服务器部署：`cd /opt/cmd/src/c && make && make install`
- 功能验证：
  - `cmd dhcp` → 原交互菜单不变
  - `cmd dhcp 1` → 直接执行 `systemctl status isc-dhcp-server`
  - `cmd dhcp 99` / `cmd dhcp abc` → 提示"无效的序列号"安全退出
