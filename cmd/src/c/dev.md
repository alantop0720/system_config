# 开发日志

## 2026-09-06 cmd 支持 `cmd 菜单名 序号` 直接执行菜单项

### 需求

原来运行 `cmd dhcp` 只能弹出菜单后手动输入序号选择。新增功能：支持在命令行直接带序号参数执行对应菜单项，例如 `cmd dhcp 1` 直接运行 dhcp 菜单里的第 1 项，不再需要手动选择。不带参数时（`cmd dhcp`）保持原有交互菜单行为不变。

### 改动文件

#### 1. `cmd/src/c/cmd.c`（核心改动）

`main()` 中在 `processCommandFile()` 解析完菜单文件之后：

- 若 `argc >= 3`（命令行带了序号参数）：直接 `choice = atoi(argv[2])` 作为序号，跳过"请输入要执行的序列号"提示、`scanf` 和清空输入缓冲区这三段交互代码。
- 否则：保持原有交互流程不变。
- 序号范围校验（`choice < 1 || choice > commandCount` → "无效的序列号"）位置不动，两种方式共用：非数字参数 `atoi` 得 0，同样被范围校验安全拦截。
- 之后的执行分发逻辑完全未动：flag=1 直接 `system()` 执行；flag=0 仍走 `[key]` 运行时交互输入。

#### 2. `cmd/readme`（帮助文档，`cmd` 无参数时显示）

- 新增用法说明：`cmd 菜单名 交互选择菜单项` / `cmd 菜单名 序号 直接执行对应菜单项，例如 cmd dhcp 1`
- 更新日期改为 2026.09.06。

#### 3. `cmd/src/c/AGENTS.md`（开发文档）

补充 CLI 用法说明：`cmd`（显示 readme）、`cmd <菜单>`（交互选择）、`cmd <菜单> <序号>`（直接执行）。

### 测试验证

gcc `-fsyntax-only` 语法检查通过。功能测试（利用临时目录模拟 `/opt/cmd`，测后已删除）：

| 场景 | 结果 |
|------|------|
| `cmd dhcp 1` | 打印菜单后无输入提示，直接执行第 1 项命令 |
| `cmd dhcp 99` | 报"无效的序列号"，退出码 1 |
| `cmd dhcp abc` | 报"无效的序列号"，退出码 1 |
| 管道输入 `2` 给 `cmd dhcp` | 原交互模式正常，仍提示输入序号 |

### 部署

源码改动需在 Linux 服务器上重新编译安装才能生效：

```bash
cd /opt/cmd/src/c
make && make install
```

### 备注

- 该能力对所有菜单通用（不止 dhcp），如 `cmd firewalld 1`、`cmd disk 1` 同样适用。
- 顺带发现的问题（本次未修）：`cmd\disk` 数据文件第 19–21 行有一项"描述/flag/命令"三行顺序写反，解析后该项 flag 变 0、命令变成 `1`，会执行错误命令，待后续修复。
